About

I'm an embedded software engineer at Streambow, where I develop C software for telecom network gateway devices running embedded Linux, integrate containerised components into network diagnostics pipelines, and debug networking behaviour down at the packet level.

I got here through 42 Lisboa, whose project-based curriculum I completed in May 2025 with a specialisation in systems and network programming. That's where I picked up the habit of building things from the bottom up — reimplementing ping, traceroute, malloc and a Unix shell rather than reading about them.

What I care about now is the whole path from a low-level primitive to something people actually use. Quest Board is the clearest example: a Go and React application I designed, shipped, and now operate in production — versioned releases, CI-gated merges, a monitoring stack, and an on-call runbook for when it breaks.

Quest Board

Self-hosted D&D campaign platform — designed, shipped and operated

Live

A full campaign toolkit — quest board, character builder, battle maps with server-side fog of war, encounter builder and initiative tracker. A React 19 SPA is compiled and embedded into a single Go binary, so the whole application deploys as one container behind a Cloudflare Tunnel with no exposed ports.

  • Contract-first: one OpenAPI spec generates both the Go server interface and the typed TypeScript client.
  • Security: Discord/Google OAuth plus local accounts, TOTP two-factor with recovery codes, end-to-end HTTPS.
  • Operated for real: ~49k lines, 185 merged PRs, CI-gated main, staging and production pipelines, nightly backups, a written runbook.

Homelab Observability

The monitoring stack that watches Quest Board in production

Running

One Prometheus and Grafana stack for the whole host, deliberately kept in its own repo so monitoring never shares an application's lifecycle — Grafana stays reachable precisely when a service is down. Adding a service takes one target file and no restart.

  • Coverage: application metrics, postgres-exporter, node-exporter and cAdvisor for host and per-container usage.
  • Alerting as code: provisioned rules for service-down, 5xx rate, disk pressure and DB pool saturation, routed to Discord.
  • Locked down: Prometheus and /metrics never leave the LAN; only Grafana is published, behind Cloudflare Access.
